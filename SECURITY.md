# Security Policy

## Reporting a Vulnerability

Do not open public GitHub issues for suspected security vulnerabilities.

Until a dedicated private security contact is added, use the most private reporting path available through GitHub for
this repository. If private reporting is not enabled, add one before broad public distribution.

When reporting a vulnerability, include:

- a clear summary of the issue
- affected components or files
- reproduction steps or proof of concept, if safe to share
- impact assessment
- any suggested mitigation, if known

## Response Expectations

Maintainers should aim to:

- acknowledge receipt promptly
- reproduce and assess the issue
- coordinate a fix
- disclose publicly after a fix is available, when appropriate

## Scope

Security issues include, but are not limited to:

- auth bypass
- secret exposure
- unsafe execution boundaries
- injection vulnerabilities
- privilege escalation
- sensitive data leakage

For ordinary bugs, use the normal issue tracker instead of the security reporting path.
